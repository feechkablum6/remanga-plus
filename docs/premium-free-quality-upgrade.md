# Улучшение качества главы на лету

## Зачем

Источники Premium Free сильно различаются по качеству сканов, а раньше глава
показывалась от того источника, который **ответил первым**. Быстрее всех обычно
отвечает wamanga, у которого страницы самые мелкие: на проверенной главе 494 px
ширины против 690 px у teletype. Качество, по сути, определялось сетевой удачей.

Ждать лучший источник целиком — значит задерживать открытие главы на секунды.
Поэтому сделано двухфазно: сначала быстрый показ, потом тихая подмена.

## Как работает

**Сервер** (`parser-server/src/resolve-chapter.ts`):

1. Все провайдеры стартуют параллельно.
2. Первый успех сразу уходит клиенту — глава открывается без задержки.
3. Провайдеры **выше** по `providerPriority` продолжают работу; те, что ниже,
   отменяются — улучшить результат они не могут.
4. Когда лучший по приоритету заканчивается, результат кладётся в сессию через
   `onUpgrade`, а `onSearchComplete` помечает, что ждать больше нечего.

Клиент забирает его через `GET /api/chapters/upgrade/:sessionId`:

| Ответ | Значение |
|-------|----------|
| `{status:"pending"}` | поиск ещё идёт, опрашивать дальше |
| `{status:"ready", result}` | пришёл источник лучше, можно подменять |
| `{status:"none"}` | лучше не будет (в том числе если сессия истекла по TTL) |

**Клиент** (`src/premium-free-upgrade.ts`, `src/reader-enhancer.ts`):

1. `pollPremiumFreeUpgrade` опрашивает эндпоинт в фоне (интервал 1,5 с, потолок
   45 с).
2. Все страницы нового источника скачиваются и декодируются заранее
   (`preloadPremiumFreePageImage`).
3. Если хоть одна не загрузилась — подмена отменяется целиком: смешивать два
   источника в одной главе нельзя.
4. Секция перерисовывается через `renderPremiumFreeFeedPagesPreloaded` — каждой
   картинке проставлены `width`/`height`, поэтому итоговая высота известна сразу.
5. `computeScrollAfterSwap` возвращает новое положение прокрутки.

## Почему скролл не дёргается

Нарезка страниц у источников разная — на одной и той же главе 14 страниц против
35, и суммарная высота меняется. Поэтому положение восстанавливается по смыслу,
а не по пикселям:

- читаем внутри главы → сохраняется **доля** прочитанного внутри неё;
- глава уже выше экрана → прокрутка сдвигается на разницу высот, чтобы контент
  под ней не уехал;
- глава ещё ниже экрана → ничего не трогаем.

Всё это делается одним синхронным блоком, без анимации и без `scrollIntoView`.
